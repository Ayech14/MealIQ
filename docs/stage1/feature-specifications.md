# Detailed feature specifications

All features are available through the planned React GUI and Python Typer CLI through `MealPlanningFacade`; FastAPI delivery adapters expose the shared application boundary. The GUI interaction below names the principal screen. The CLI accepts equivalent commands/options or a natural-language command where applicable. “Hybrid” means the external LLM API may interpret, reason, rank, or propose through `LLMClient`, while deterministic services retain validation and state authority.

| ID | Feature and description | GUI interaction; input -> output | Type and expected workflow | Errors / alternatives |
|---|---|---|---|---|
| F01 | **User goals and preferences.** Maintain goals, nutrition preferences, dietary restrictions, allergies, likes/dislikes, meals/day. | Profile screen; `UserProfile` fields -> validated saved profile. | Deterministic. `ProfileService.updateProfile()` validates then persists; agent receives the profile as planning context. | Invalid meal count/target rejected; allergies conflict with a preferred food is flagged for resolution. |
| F02 | **Pantry inventory management.** Add, update, remove, and inspect stocked ingredients and optional expiry. | Pantry screen; ingredient, quantity, unit, expiry -> current inventory. | Deterministic. `PantryService` validates and updates `Pantry`; event informs dependents. | Unknown unit/negative quantity rejected; expired items are shown but not counted as available. |
| F03 | **Recipe search and recommendation.** Retrieve/rank recipes fitting pantry, meal type, dietary needs, goals, time, and budget. | Recipe browser/filter panel; criteria -> compatible ranked recipes and exclusions. | Hybrid. `RecipeTool.searchRecipes()` retrieves/filter candidates; agent explains/ranks; validators enforce hard constraints. | No exact match returns near matches with explicit violated soft constraint, or invites generation. |
| F04 | **AI recipe generation.** Produce a custom structured recipe when retrieval is insufficient or requested. | Recipe generator; desired meal/constraints -> schema-valid candidate recipe. | Hybrid. `PromptBuilder` and `LLMClient` use `ProviderLLMAdapter` to call the planned external LLM API; `ProposalValidator` and `NutritionService` validate the proposal before display/save. | Malformed output retries once or returns a clear failure; hard restriction breach is rejected. |
| F05 | **Weekly meal-plan generation.** Create a multi-day plan with the requested meals/day. | Calendar “Generate plan”; period and constraints -> `MealPlan`, rationale, conflicts. | Hybrid. Agent orchestrates recipe retrieval, nutrition and grocery projections, and a planning strategy; deterministic gate validates feasibility. | Conflicting constraints produce alternatives/trade-offs; no silent over-budget/time plan. |
| F06 | **Nutrition analysis.** Calculate calories, protein, carbohydrates, fat, and totals for meal/plan. | Nutrition panel; recipe/plan and servings -> nutrient breakdown. | Deterministic. `NutritionService.calculateNutrition()` totals ingredient data. | Missing nutrition data is labeled incomplete; the unknown value is never invented. |
| F07 | **Grocery-list generation.** Determine ingredients absent from pantry for a selected plan. | Grocery screen “Generate”; plan and pantry snapshot -> raw required list. | Deterministic. `GroceryService.generateList()` subtracts usable inventory from recipe requirements. | Incompatible units/unmapped ingredient cause a resolution request, not unsafe arithmetic. |
| F08 | **Grocery-list optimization.** Consolidate duplicate needs and keep purchase total within budget where feasible. | Grocery screen “Optimize”; raw list, price data, budget -> consolidated list, estimate, warnings. | Deterministic with agent-supported alternatives. `optimizeList()` consolidates/counts; agent may propose compatible substitutions if over budget. | Missing price yields partial estimate; unavoidable budget conflict is reported. |
| F09 | **Ingredient substitution.** Replace unavailable/disliked/unsuitable ingredients compatibly. | Recipe/plan substitution action; target ingredient and constraints -> candidate substitutions and selected replacement. | Hybrid. Agent proposes; `SubstitutionTool` checks catalog; validators enforce allergies, restrictions, nutrition/time/budget rules. | No valid substitution leaves the recipe unchanged and reports alternatives. |
| F10 | **Natural-language meal-plan modification.** Interpret requests such as “make Wednesday dinner vegetarian.” | Calendar chat/editor; text instruction -> previewed `PlanChange` and updated plan on confirmation. | Hybrid. Agent interprets command; `PlanChangeCommand` applies/undoes deterministic mutation; revalidation/grocery refresh follow. | Ambiguous date/meal asks a clarifying question; infeasible change returns options. |
| F11 | **Cooking-time-aware planning.** Respect per-day and per-meal limits. | Time constraints panel/calendar; limits -> time-compatible plan or conflicts. | Hybrid. Strategy/agent selects candidates; `ConstraintValidator.validateTime()` enforces minutes. | If none fit, list fast alternatives or explain the unsatisfied limit. |
| F12 | **Budget-aware planning.** Use a weekly/period budget in selection, list creation, and substitutions. | Budget control; currency amount/period -> plan/list estimate and status. | Hybrid. `BudgetStrategy` ranks trade-offs; `BudgetService` calculates and validates. | Impossible budget reports exact shortfall and suggested compromises. |
| F13 | **Dynamic plan adaptation.** Revise affected plan/grocery items after pantry, budget, time, or preference changes. | Pantry/profile/calendar changes or natural-language request -> impact preview and adapted plan. | Hybrid. `MealPlanImpactObserver` identifies affected meals and `GroceryListImpactObserver` marks lists stale; the agent proposes changes and commands apply them after confirmation. | If adaptation fails, preserve current plan and present affected meals/conflicts. |
